# Windows Utility Pack 1.0.0

This release revives the existing 52-tool Windows desktop application with
stronger file/state protection, repaired native workflows and a per-user installer.

## Downloads

- `WindowsUtilityPack-1.0.0-win-x64-setup.exe`: per-user setup with a Start Menu shortcut.
- `WindowsUtilityPack-1.0.0-win-x64-portable.zip`: extract the complete folder and run `WindowsUtilityPack.exe`.
- `SHA256SUMS.txt`: SHA-256 checksums for both packages.

Both packages bundle the .NET desktop runtime. They are unsigned; Windows may
display an unknown-publisher warning. No image-processing license key is required.
yt-dlp, gallery-dl and FFmpeg remain optional downloads managed by the app.

## Changes

- Replaced ImageSharp with Magick.NET, repaired image and QR exports, and corrected
  screenshot annotation coordinates, undo and output-layer handling.
- Added atomic file publication, stronger duplicate-cleanup checks, staged batch
  renaming, bounded text/network work and cancellation handling.
- Protected saved request credentials with current-user Windows encryption and
  upgraded the local vault to authenticated encryption with encrypted backups.
- Repaired environment scope selection, nullable scheduled-task dates, the blank
  Diff Tool, desktop color sampling, navigation lifetimes and overlapping controls.
- Repaired downloader provisioning, concurrent output names, gallery history and
  custom speed-test endpoints.
- Added repeatable external native scenarios for every tool, disposable Windows
  fixtures, installer lifecycle coverage and independently checked output files.

## Upgrading and limits

Close older app instances before updating. Back up both
`%LOCALAPPDATA%\WindowsUtilityPack` and `%APPDATA%\WindowsUtilityPack` first.
Uninstall retains the user profile and files the installer did not create.

The installer update scenario uses a generated older-version package. A separate
native migration scenario uses the actual published `v0.1.0-alpha` executable to
create a vault, then checks migration, retained encrypted copies and reopening in
the new app. Other historical/custom data combinations are not exhaustively covered.
Do not reopen a migrated vault in the alpha build or overwrite it with old data.

The [native acceptance report](../NATIVE_ACCEPTANCE.md) and
[workflow matrix](../REVIVAL_WORKFLOW_MATRIX.md) define the recorded scope.
Broader authenticated providers, display configurations and sustained resource
workloads remain additional acceptance work. Provider HTTP blocking can prevent
downloads independently of the application.
